# Astro Archive · Plugin API v1

Плъгинът е отделна папка с `plugin.json`, `main.py` и собствените си модули/ресурси. Не редактира Backend, Bridge или UI и не импортира техни вътрешни класове. Общува с приложението чрез подадения `context`. Настройките и временните данни са негови; основните услуги се използват само чрез описаните команди и разрешения.

## Бърз старт

1. Копирай `.examples/sample-tools` в `Plugins/sample-tools`.
2. Промени `id`, име и описание в `plugin.json`. Името на папката съвпада с `id`.
3. Напиши собствената логика в `main.py` и собствени модули. Входът е `setup(context)`; той връща функция за освобождаване на ресурси.
4. От Настройки → Плъгини обнови списъка, включи плъгина и разреши описаните UI допълнения. Променен код изисква ново потвърждение.

Примерът не се зарежда автоматично: папката `.examples` умишлено се пропуска при откриване.

## SDK команди

| Команда | Роля |
|---|---|
| `context.command(name, handler)` | Регистрира собствена команда. Името автоматично получава префикса на плъгина. |
| `context.publish(contribution_id, elements)` | Изпраща описание с данни за UI. Bridge валидира и визуализира готовите контроли. |
| `context.settings()` | Чете собствените запазени настройки. |
| `context.save_settings(dict)` | Записва собствените настройки. |
| `context.storage()` | Дава собствената папка за данни на плъгина. |
| `context.host(command, parameters)` | Извиква именувана основна услуга само ако разрешението я допуска. |
| `context.capability(id, parameters)` | Използва декларирана възможност на друг включен плъгин. Изисква `capabilities.invoke`. |
| `context.task(title, work, section)` | Пуска собствена фонова задача. `work(cancel, progress)` следи `cancel.is_set()` и извиква `progress(done, total, description)`. |
| `context.processing(action, parameters, cancel, progress)` | Разрешен достъп до управлявани работни копия и външни програми. Изисква `processing.manage`. |
| `context.remote(action, parameters)` | Хост адаптер за мрежов плъгин: именувани команди, UI ресурси и трансфери по ID. Изисква `remote.host`. Удостоверяването и мрежовата политика са в самия плъгин. |

## Данни от UI към плъгина

Контролът има `command`, който сочи към регистрирания handler. Bridge подава:

```python
{
  "element": "calculate",        # ID на натиснатия контрол
  "values": {"count": 10},      # валидирани стойности на полетата
  "row": 0,                      # само при избор в таблица
  "selected": {"x": 0, "y": 0}, # избраният табличен ред
  "context": {"ids": [], "archiveId": "frames", "stage": "data"}
}
```

Няма достъп до произволна функция по име. Позволени са само регистрирани команди, видими и активни контроли и текущото одобрено допълнение. `context.ids` изисква `archive.read`.
Handler връща JSON-съвместим резултат; `message` показва уведомление, `copyText` заявява копиране на текст, а `navigation` с `archiveId` и `relativePath` заявява навигация. За обновяване на собствените полета извикай отново `publish`.

## Места за визуализация (`slot`)

- `archive`: допълнение в архива.
- `analysis`: отделно действие/панел при анализ.
- `analysis-tools`: компактни декларативни контроли до готовата основна диаграма. Не заменят основния анализ. При действие получават `context: {ids, archiveId, stage}` за всички кадри в показания обект/вечер, независимо от маркираните точки и ръчното изключване. Големи изображения не се зареждат автоматично.
- `preparation`: отделно действие/панел при подготовка.
- `settings`: настройки на плъгина в неговото меню.
- `customization`: визуални настройки на плъгина.
- `header`: компактни индикатори под информацията за диска.

Едно допълнение има `id`, `slot`, `title`; по желание `description`, `activate` (команда при отваряне), `clients: ["desktop", "remote"]`. Ако `clients` липсва, важи за двата вида интерфейс. Например индикаторът на Remote Operation е само за `remote`.

## Библиотека от UI контроли

За всички важат `type`, уникално `id`, по желание `label`, `help`, `visible`, `disabled`, `span` (1 или 2).

| `type` | Основни свойства |
|---|---|
| `text` | `value`, `tone` |
| `metric` | `value`, `unit`, `tone` |
| `input` | `value`, `placeholder`, `maxLength`, `command` |
| `number` | `value`, `min`, `max`, `step`, `command` |
| `checkbox` | `value`, `command` |
| `select` | `value`, `options: [{value, label}]`, `command` |
| `button` | `command`, `tone` |
| `group` | `children` със същите видове контроли |
| `table` | `columns: [{key, label, format}]`, `rows`, `command` при избор на ред |
| `list` | `items: [{id, label, description?, status?, tone?, disabled?}]`, `command`, `actionLabel`; отделно действие вдясно на всеки ред |
| `chart` | `chartType` (`line`, `scatter`, `bar`), `series`, `xLabel`, `yLabel` |
| `console` | `value` (текст) |
| `image` | `value: "data:image/png;base64,..."` |

`tone`: `normal`, `primary`, `success`, `warning`, `error`.
Табличен `format`: `text`, `number`, `exposure`.
Серия: `{name, color: "#70bfff", points: [{x: 1, y: 2, label: "A"}]}`.
Няма HTML, JS, `onclick` или произволни адреси в тези описания.

Действието на ред в `list` изпраща `itemId`, а Bridge подава на handler `selected` с текущия разрешен ред. ID са уникални низове до 120 знака: букви, цифри, `:`, `_`, `-`. Не се използва позиционен индекс: премахнат, непознат или изключен ред се отказва. Например `selected['id']` избира точния екип. До 1000 реда; само данни, без изпълним код.

### Снимки само при нужда

Плъгинът описва `image` с PNG данни. Bridge ги задържа в ограничен ресурсен кеш и заменя съдържанието с непрозрачен `assetId` в списъците и събитията. Изображението се изтегля отделно само при показване на съответния видим контрол; повторното описание на панела не носи повторно PNG байтовете. Достъпът се проверява отново по активен плъгин и разрешен UI. След изключване ресурсите стават недостъпни. Не е нужно авторът да пише файлов сървър или да променя основния код за това.

### Локални измервания на клиента

За хост адаптери като Remote Operation има клиентска команда `AstroArchiveExtensions.setClientValues(pluginId, contributionId, updates)`. Тя обновява само вече декларирани и разрешени `text`/`metric` контроли в `header` на това устройство. Приема само `value` (текст), `tone`, `unit`. Не добавя HTML, команди или нови контроли и не променя състоянието на други потребители. Например времето за отговор на телефона не се изпраща като общо състояние до всички устройства.

| Разрешение | Налични основни команди / роля |
|---|---|

| `analysis.read` | `python.analysis.result` |
| `preparation.read` | `python.preparation.state` |
| `capabilities.invoke` | `bridge.capabilities`, `bridge.capability.call` и `context.capability` |
| `processing.manage` | Управлявани работни копия и потвърдено прибиране през processing адаптера |

Точните договори за разширени processing/remote действия са в `Bridge/Plugins/host_services.py`, `Backend/Preparation/exchange.py` и използващите ги отделни плъгини. За обикновен UI плъгин те не са необходими. Примерът показва полета, бутон, таблица, диаграма и собствени настройки без никакви разрешения към архива.

## Граници и ограничения

API v1 е архитектурен договор, а не ОС изолация на Python. Инсталирай само доверен код. Няма автоматична инсталация на Python зависимости. Данните към UI са JSON-съвместими; до 200 контрола на допълнение, до 6 нива групи, до 10 000 таблични реда и до 5 000 точки на серия. Изображенията са PNG до 4 милиона пиксела; целият UI документ е ограничен до 2 MB преди извличане на ресурсите. Ресурсният кеш е до 32 изображения / 32 MB на включен плъгин.

При изключване Bridge премахва контролите и командите, прекратява собствените задачи на плъгина и извиква върнатата от `setup` функция за освобождаване. Авторът затваря там собствените си нишки, процеси и връзки. При дълга работа проверявай отмяната и не блокирай обработчика на UI команда.


## Обща работна сесия (Bridge, протокол 1)

Всички удостоверени клиенти на един хост следват общ работен изглед. Състоянието е в Bridge/Core/session.py, а UI адаптерът е UI/Shared/Web/session.js. Изчисленията остават в съществуващите Python услуги; мрежовият транспорт и дистанционната политика остават в Remote Operation.

| Команда за основния UI | Предназначение |
| --- | --- |
| `ui.session.get` | Малко описание на променените канали според известните версии. |
| `ui.session.publish` | Проверен избор на раздел, архив, данни, изглед, оси, подбор и ориентация. Изисква текуща версия, идентификатор на клиент и пореден номер. |
| `ui.session.resource` | Изрично поискан готов ресурс за активния изглед: покритие, звездна референция, серия или отчет за изнасяне. |
| `ui.session.export` | Съхраняване на заявеното превю на диаграма отделно от събитията на сесията. |
| `ui.session.sources` | Една заявка за имената и обобщенията на източниците на съществуваща подготвителна задача. |

Това са команди на основния UI и ограничената remote.host връзка. Не добавят ново разрешение за `context.host` на обикновени плъгини.

Авторът на плъгин продължава да използва `context.publish` с готовите декларативни компоненти. След проверка/запис на входа публикувай актуалните стойности; те се предават на останалите клиенти. Избраният разрешен панел се споделя автоматично. Възстановяването на панела при наблюдател или нов клиент не извиква повторно `activate` или команда за обработка. Не използвай визуално възстановяване за стартиране на задачи.

Не се предават HTML, JavaScript, произволни команди или кликове. Недостъпните дистанционно възможности запазват ограниченията си. Изборът на външни програми, системните диалози и свалянето на файл към конкретното устройство не се възпроизвеждат върху другите устройства. Метриката за мрежова връзка остава индивидуална за клиента.

Събитията `ui.session.changed` носят само канал, версия и автор. Пикселите на изображенията и големите аналитични ресурси се изтеглят при отваряне на съответния изглед. Работната сесия се пази докато хостът работи; профилът, индексите, решенията за подбор и записаните отчети запазват съществуващото си съхранение.


## Архивни папки за плъгини (`archive.manage`)

`context.archives(action, parameters)` е общият Bridge адаптер за добавяне на папки към обичайния архив. Не отваря портове и не управлява SMB, TLS, Windows потребители или пароли. Транспортът и проверката на шифроването са изцяло в мрежовия плъгин.

| Действие | Вход и резултат |
|---|---|
| `list` | Връща `archives` с ID, име, тип и папка. Не чете съдържанието на архивните изображения. |
| `register` | `key`, `name`, `kind`, по желание `structure`, `managedStructure`, `previousId`; регистрира собствен архив с празна папка и устойчив ID. Повторно извикване запазва избраната папка, име и потребителски изглед. `previousId` може да приеме само собствен стар SDK архив. |
| `choose` | По желание `title`; връща `path` от системния избор на папка. Само на десктопа. |
| `attach` | `path`, `name`, `kind` (`frames`, `stacks`, `photos`), по желание `identity` (UUID); добавя архив и връща неговото `id`. С `id` настройва само вече регистриран собствен архив и връща пълния запис в `archive`. Запазва структурата, не копира файлове и не пренаписва маркери в папка само за четене. |
| `detach` | `id`; премахва само допълнителен архив, добавен от същия плъгин. Не изтрива данни. |
| `refresh` | `id`; пуска обичайната задача за индексиране на този архив. |
| `hold` | `active` (boolean); държи хоста жив, докато плъгинът управлява активен ресурс. При изключване Bridge освобождава задържането. |

Подпапки на съществуващ архив не могат да се добавят като отделни архиви. Програмната папка и целият диск също се отказват. Изчисленията, редакцията на метаданни, внасянето и подготовката продължават през съществуващите услуги. Всеки компютър пази локален SQLite индекс; не споделяйте самата програмна база данни.

За току-що създадена празна архивна папка `attach` приема и `initialize: true`: създава липсващия стандартен архивен маркер с посочения UUID. При обикновено свързване флагът се пропуска, за да не се записва нищо в папка само за четене.

Собствени настройки под общия редактор на архива: добавете contribution със `slot: 'customization'` и `archiveKey`, равен на ключа от `register`. UI го монтира само под архива на същия плъгин и го обозначава като плъгин. Използвайте обичайния `context.publish`. `activate` тук трябва само да синхронизира настройките; извиква се след изрично запазване на архивните места. Резултат `archiveSettings: result['archive']` от `attach` синхронизира местоположението в отворения редактор, като запазва останалите незапазени промени.

`managedStructure: true` означава, че физическата подредба се управлява от плъгина. Общият редактор предоставя имена за показване, икони и колони, без действие за физическо пренареждане. Смяната на папка при активна задача на собственика се отказва. В Backend няма специфична логика за IASC.

## Инспекция на кадри (`analysis.inspect`)

`context.inspection(action, parameters, cancel=None, progress=None)` е общ локален SDK за измервания и предупреждения. Реализацията е в `Bridge/Plugins/inspection_services.py`. Плъгинът не внася Backend модули и не копира кода за FITS, PSF, регистрация или основния viewer. SDK не съдържа ML модел или разпознаване на конкретни дефекти.

| Действие | Договор |
|---|---|
| `archives` | Връща `archives: [{id, name, kind}]` за видимите архиви на кадри; без файлови пътища. |
| `selection` | Текущият подбор на основния анализ: `ids`, `reportId`, `kind`. С `scope: "report"` връща всички ID на текущия отчет, без да зависи от маркираните точки. Само състояние, без пиксели. |

| `limits` | Зададените от потребителя `memoryMb`, `workers`. |
| `prepare` | `ids` (1–5000), по желание `reportId`, `force`; връща обичайния отчет за качество. Преизползва валидни измервания при съвпадащ размер/mtime; иначе използва основната услуга. `referenceFrames` съдържа необходимите референции при избран поднабор. Изпълнявайте през `context.task`; `progress(done,total,label)` и `cancel.is_set()` са стандартните механизми. |
| `sample` | `id` от индекса, `edge` 128–1536; връща локален NumPy `image`, `pixelToSample` (матрица от оригиналните центрове на пикселите към работните), `nativeShape`, `step`, `channel`, `signature` (`size:mtime_ns`). Използва същата зелена/монохромна равнина като основния анализ и усредняване на блокове; не променя оригинала. Не публикувайте масива в UI. |
| `warp` | Локален `image`, крайна обратима хомография `matrix`, `shape: [height,width]` до 1536, `order` 0 или 1, по желание `cval`. Използва съществуващото подравняване. |
| `show` | `id`; изрично отваря стандартния споделен viewer. Пиксели се четат само след това действие. |
| `annotate` | `reportId`, `annotations: [{id, warnings: [{type,score,message,severity}]}]`, по желание `present: true`. Типове: `cloud`, `satellite`, `obstruction`; оценка 0–1, текст до 400 знака, тежест `low`, `medium`, `high`. Заменя само предупрежденията на извикващия плъгин. Не приема решение за включване/изключване. Проверява принадлежност към отчета и актуалност на файла. |

`annotate` обновява препоръките и общата диаграма, но никога ръчните решения, архива или оригиналите. `present: true` показва основния резултат вместо активния разширен панел; отказва по време на основен анализ. Резултатът съдържа `decisionsChanged: false`, `originalsChanged: false`. За сигурност това е отделно разрешение от `analysis.read`.

`annotate` приема и `highlight: true`: при същия все още активен отчет включва маркерите за предупреждения и маркира само кадрите с нови предложения от подадените анотации. Не променя ръчните решения и не превключва към отделен плъгин панел. Ако потребителят вече е отворил друг отчет, той не се заменя.

Ръчните решения през основния Bridge изчистват маркирането само на засегнатите ID и увеличават `decisionRevision` в общата сесия. UI синхронизацията отхвърля чакащото старо маркиране при нова ревизия на решенията, без да изхвърля чакащите промени по филтри/оси.

Предупреждение може да съдържа и `origin: "ai"` или `"algorithm"` (по подразбиране). Това е описание за визуализация, не право за промяна на решение. Основната диаграма показва △ за обичаен алгоритъм, □ за AI и ■ при наличие и на двата вида предупреждения. `source` продължава да се задава от Bridge на действителния плъгин и не може да се подменя от него.

SDK е локален Python интерфейс. Не предлага произволни файлови пътища, мрежов транспорт или системни команди. Не е ОС изолация: инсталирайте само доверени Python плъгини. Големите числови масиви не се сериализират в общата сесия; за заявени изображения използвайте декларативния `image` контрол с непрозрачен ресурсен ID.
Допълнение за инспекционни анотации: всяка анотация в `context.inspection('annotate', ...)` може да включва `quality` — крайна стойност от 0 до 100 или `null` при ненадеждно измерване. Тя се пази към източника на плъгина в `inspectionMetrics`, без промяна на потребителския подбор. Допустимите видове предупреждения включват `cloud`, `satellite`, `obstruction`, `light` и `quality`. Индексът трябва да бъде обозначен като ориентировъчен, ако не е калибриран. Обновяването на анотации валидира същите ID и размер/време на източника и изпраща обновяване на общата сесия.



## Общ преглед на изображение — viewer-tools

`slot: "viewer-tools"` поставя стандартни декларативни контроли в общия преглед на Архив, Анализ и Подготовка. `activate` получава `context: {stage: "viewer", viewerId, ids}` при смяна на изображението. При действие този контекст се взема от текущия преглед, а не от отложена глобална селекция. Не публикувайте пътя като UI текст.

`context.inspection("source", {viewerId})` изисква `analysis.inspect` и връща само отворено от хоста изображение: локален `path`, `id`, `archive`, `relative`, `size`, `mtime`, `fingerprint`, `name`, `kind`, `group`. Вариантът `{id}` разрешава само активен архивен запис. Няма вход за произволен път. Преди повторна употреба проверете ID и сигнатурата; ако източникът е сменен, поискайте нова оценка.

### Възможност inspector.training.v1

Предоставя се от AI Frame Inspector. Извиква се с `context.capability("inspector.training.v1", {...})`; изисква `capabilities.invoke` и включен инспектор. `operation: "measure", ids: [...]` връща измервания само за зададените ID и версия на признаците; за научния фон използва кадрите от съответния обект/телескоп/вечер/филтър. Не променя подбора или видимия анализ. До 1000 учебни ID, 1500 кадъра в група и 5000 контекстни кадъра. `operation: "activate", model: {...}` приема само валидиран числов JSON модел, пази предишния и го използва при следващата изрично стартирана AI проверка. Не се зареждат pickle или изпълним код.


`inspector.training.v1`, operation `measure`, вече връща `featureSchema: 2` и речник с 48 признака (33 числови + 15 флага за липсващи измервания). При `compact: true` всеки ред има `qualityValues: [числа...] | null` по реда на `features`, плюс `id/sourceSize/sourceMtime`; имената се изпращат веднъж. Без `compact` се запазва вариантът `qualityFeatures` с речник. При обучение изисквай съвпадение на схемата и източника; никога не смесвай механично различни версии. Новите числови модели са `frame-inspector-user-quality-v2`; инспекторът валидира и използва и предишните модели v1 с 18 признака.


`inspection("source", {viewerId})` разрешава архивния ID и за прегледи, отворени с навигация по файлове. `inspection("source", {saved:{path,size,mtime}})` е ограничено повторно намиране на вече индексиран файл под настроен архивен корен. Изисква `analysis.inspect`; няма браузърна RPC команда за произволни пътища. При нееднозначно съвпадение или променена сигнатура се отказва. Достъпът е по индекса; няма сканиране и няма четене на пиксели.

### Проследими измервания за обучение

Съществуващият синхронен measure остава съвместим. За интерактивни обучители използвайте:
- measure-start с ids и compact: true → ticket и taskId; връща веднага.
- measure-status с ticket → state (running/completed/failed/cancelled/delivered), message, fraction (0..1, само текущото измерване), updated (Unix секунди). Няма пиксели/признаци в статуса.
- measure-result с ticket → същия пакет като measure, еднократно след completed. След това билетът е delivered; повторен резултат се отказва.
- measure-cancel с ticket → иска безопасно спиране. Отказът се проверява при подготовката, измерванията и инспекцията. Изчаквайте приключването на текущата операция.

Един инспектор има само едно активно измерване и пази най-много един резултат в паметта; ново measure-start обезсилва старите билети. Невалиден/стар ticket, преждевременен резултат или втора паралелна проверка се отказват. Използвайте върнатия непрозрачен билет, без файлови пътища. При изключване на инспектора задачата се отменя. Тези операции са локална capability, не нови браузърни RPC команди.


### Каталожно подравняване и покритие на инспекция

inspection("register", {reportId, sourceId, targetId}) преизползва съществуващия алгоритъм за подравняване върху звездните каталози от посочения готов отчет. Двата ID трябва да са вътре в отчета; проверява се текущата файлова сигнатура. Връща matrix/rms/matched или matrix: null при липса на надеждна връзка. Матрицата е в първоначални пиксели, source → target. Не чете FITS пиксели, не променя глобалните трансформации/подбор и не приема файлови пътища. Краткият ограничен кеш се обезсилва чрез reportId/сигнатурите. Разрешение: analysis.inspect.

Анотацията може да включва comparison: {coverage, references, matchedStars, reason}. coverage е число 0..100 или null; references — цяло 0..16; matchedStars — цяло 0..2000; reason — текст до 400 знака. Записват се като допълнителни inspectionMetrics на подателя. Покритието е обхват на сравнението, не оценка за качество или вероятност. Нулево покритие не е основание за лош статус и не променя решението на потребителя.



## Подготовка, незавършени сесии и текстови отчети

Обновлението за IASC 0.4.0 добавя общи SDK възможности, без специфичен IASC код в Backend:

- `slot: "preparation"` създава карта след избора на данни. Горно дублиращо меню няма. `order` е цяло число от -1000 до 1000, по подразбиране 0; по-малките са първи.
- `slot: "preparation-activity"` показва публикуваните елементи отдолу, независимо коя подготовка е отворена. Публикувайте `[]`, ако няма започнати незавършени сесии. Не показвайте запазена сесия като жив процес, ако не сте потвърдили, че процесът работи. Състоянието и съхранението са в плъгина.
- Бутон/ред в този слот може да изпълни плъгин команда. Отговор `{ "openContribution": "my-preparation" }` отваря одобреното `preparation` допълнение **на същия плъгин**, без повторно активиране и подмяна на възстановения подбор.
- При команда, която започва задача, отговор `{ "taskId": "...", "returnToPreparation": true }` връща началния подбор само след успешно приключване. Грешка или отменяне оставят работния изглед достъпен. При връщане ръчно незаписаният текст се изпраща преди смяната на изгледа.
- `type: "textarea"`, `value`, `maxLength` (до 64000), `command` създава многострочен текстов вход. Съдържанието е обикновен текст, без HTML/JavaScript. Входът се валидира, запазва се чрез командата след кратък интервал и пази интервалите и новите редове. Общият вход на команда е ограничен до 300 KB.
- `context.archives("choose-file", {"kind":"report", "title":"Избери отчет"})` отваря собствен диалог за txt/psv/xml/log. `kind:"program"` избира exe. Връща `{ "path": "..." }` или празен път при отказ; само на настолния хост, с `archive.manage`. Плъгинът трябва отделно да провери размера, типа и предназначението на избрания файл. Командата не изпълнява файла и не предоставя пароли или сесии.

Архиви с `managedStructure:true` използват действителните папки при подбора в Анализ и Подготовка. Първите две нива са филтри, а всяка крайна папка с кадри се избира отделно. FITS датите и астрономическите метаданни не се заменят с имена на папки.
