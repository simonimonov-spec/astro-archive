# Astro Archive Beta 1.2.1

Beta 1.2.1 изтегля новите Windows версии директно от програмата с проверка на
SHA-256, напредък и възможност за спиране. Включва каталог за отделно изтегляне на плъгини от GitHub
и списък, който се разширява с прозореца. Чистият пакет няма папка `Plugins`,
инсталирани плъгини или лични данни.

Настолно приложение за локални астрономически архиви, FITS преглед, анализ на
кадри и подготовка за обработка. Интерфейсът се отваря в браузър; основният
Python хост слуша само на `127.0.0.1`. Плъгините се изтеглят отделно.

## Изтегляне и стартиране

1. Изтегли Windows пакета от [Releases](https://github.com/simonimonov-spec/astro-archive/releases).
   Разархивирай целия пакет в собствена папка с право за запис. Git не е необходим.
2. Отвори `AstroArchive.exe`. Стартерът показва логото, Земята и Луната в орбита
   и комета като индикатор за подготовката.
3. При липсващи компоненти прегледай списъка и избери „Изтегли“.
   Python и библиотеките се подготвят самостоятелно само за това копие.
4. При ново публикувано издание избери изтегляне, пропускане сега или пропускане
   на конкретната версия. Подготвено копие може да стартира и без интернет.
5. В Настройки → Архиви избери собствените си архивни папки. Разпространението
   не съдържа наблюдения, профил или предварително настроени лични пътища.

Подробности: [новият стартер](docs/LAUNCHER.md). Изходният ZIP от „Code“ е
за разработчици и не съдържа компилиран `.exe`. За локална разработка:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements-lock.txt
.\.venv\Scripts\python.exe start.pyw
```

Последната команда показва и грешките в конзолата. При неуспешен старт виж
`Backend/Cache/data/startup-error.log`. Не публикувай този файл без преглед.

## Системни изисквания

- Windows x64. Настолният хост, диалозите и отчитането на ресурси използват
  Windows API; поддръжка на Linux/macOS не е потвърдена.
- Python 3.13 x64 се подготвя от стартера според `requirements-lock.txt`.
- Windows .NET Framework 4.8 или по-нов за стартера.
- Microsoft Edge е предпочитаният прозорец; при липса се използва браузърът
  по подразбиране. Нужен е браузър с поддръжка на съвременен JavaScript.
- Интернет за изтегляне на програмата и Python зависимостите.
- Място за `.runtime`, локалния индекс, кеша и работните копия. Няма установен
  измерен минимум за RAM/диск; разходът зависи от размера на FITS и броя задачи.
- NumPy, SciPy, Astropy, Photutils и Pillow; точните запазени версии и техните
  зависимости са в `requirements-lock.txt`. `requirements.txt` описва диапазоните.
  GPU и PyTorch не са задължителни за основната програма.

## Какво включва основната програма

| Налично без плъгини | Отделен плъгин |
| --- | --- |
| Индексиране, търсене, филтриране и управление на архиви | Допълнителна справка по обекти: `archive-overview` |
| FITS преглед, метаданни и стандартен анализ на качество | AI оценител Beta-1: `frame-inspector-ai` |
| Стандартни диаграми, измервания и продукти за покритие | |
| Изнасяне на копия, работа с избрана външна програма, прибиране на резултати | Автоматичен Siril CLI процес: `siril-auto` |
| Локален настолен интерфейс, настройки и управление на плъгини | Дистанционен достъп: `remote-operation` |
| Локални архивни папки | Споделяне през Windows SMB: `shared-archives` |
| Основна работа със собствени файлове | Кампании и изтегляния от IASC: `iasc-campaigns` |

За инсталиране, обновяване и премахване виж [docs/PLUGINS.md](docs/PLUGINS.md).
Чистото копие няма папка `Plugins`. Настройки → Плъгини показва официалния
каталог в GitHub. Папката се създава при първото инсталиране и се премахва,
когато последният плъгин бъде изтрит. AI Trainer остава частен и не се разпространява.

## Локални данни и обновяване

`Backend/Cache/data/` се създава при работа и съдържа профил, SQLite индекс,
пътища, решения, отчети, кошче, сесии и данни на плъгините. Тази папка не е
част от изходния код. Оригиналните изображения остават в избраните архиви.

Преди обновяване затвори приложението и направи собствено резервно копие на
кеша. Разархивирай новото издание отделно; пренеси личния кеш и избраните
плъгини само локално при затворени копия. Подготви `.runtime` чрез новия `AstroArchive.exe`;
не пренасяй виртуална среда между компютри. Нов код на плъгин изисква повторен
преглед и включване.

## За разработчици и публикуване

Този раздел се отнася за изходния код в GitHub. Windows пакетът съдържа файловете за работа и потребителската документация, без тестове и помощни средства за компилиране.

- [API на плъгините](https://github.com/simonimonov-spec/astro-archive/blob/main/docs/plugin-api/API.md) и [пример за разработчици](https://github.com/simonimonov-spec/astro-archive/tree/main/docs/plugin-example).
- [Подготовка за GitHub](docs/PUBLISHING.md).
- `Tools/publication-files.json` е изричният списък за чистите хранилища.
- `py -3.13 Tools/prepare_publication.py` създава локални кандидати и пълни
  списъци за преглед. Инструментът не качва файлове и не се свързва с GitHub.
  В самостоятелно копие само на основното хранилище използвай `--core-only`.
- `py -3.13 -m unittest discover -s tests -v` проверява откриването,
  независимостта от плъгини и пакетирането. Интеграционните тестове изискват
  основните зависимости.
